# Database Schema

PostgreSQL 16. Migrations: `backend/alembic/versions`. Current head: **0007** (payment applications / valuations).

## 1. Conventions

| Rule | Detail |
|---|---|
| Primary keys | UUID v4 (`uuid`), generated by the application |
| Tenancy | Every tenant-owned table has `tenant_id uuid NOT NULL` + RLS policy `tenant_isolation` |
| Cross-tenant integrity | Composite FK `(tenant_id, child_fk) → parent (tenant_id, id)` |
| Money | `NUMERIC(19,2)` + a `currency char(3)` on the owning record. Unit rates `NUMERIC(19,6)`, quantities `NUMERIC(19,4)`, percentages `NUMERIC(5,2)` (from Phase 2 onward) |
| Timestamps | `timestamptz`; `created_at`, `updated_at` |
| Concurrency | `version integer` on user-edited aggregates (projects, companies) for optimistic locking |
| Deletion | Business records are archived/soft-deleted; audit events and document versions are immutable |
| Naming | Constraint names follow `pk_/fk_/uq_/ck_/ix_` conventions (see `app/core/db.py`) |

## 3. Tables (Phase 1)

| Table | Purpose | RLS rule |
|---|---|---|
| `tenants` | Customer organisation; `country_code` (US/GB), `data_region` (us/uk), currency, measurement system | visible if current tenant or user has active membership; insert/update only current tenant; no delete grant |
| `users` | Global identity | own row, or members of current tenant; pre-auth lookups via `SECURITY DEFINER` functions |
| `auth_sessions` | Rotating refresh tokens (SHA-256 hashed), family-based reuse detection | own sessions only |
| `password_reset_tokens` | Single-use reset tokens (hashed), 60-minute expiry (rev. 0002) | own tokens only; lookup by hash via `auth_find_password_reset_by_token_hash` |
| `permissions` | Global permission catalog (seeded) | no RLS; runtime role has `SELECT` only |
| `roles`, `role_permissions` | System roles (`tenant_id IS NULL`) + tenant custom roles | system roles readable by all; writes only to current tenant's roles |
| `tenant_memberships` | User ↔ tenant with role and status | current tenant, or the user's own memberships (to list orgs) |
| `invitations` | One-time invite tokens (hashed), 7-day expiry | tenant isolation |
| `addresses` | US (state + ZIP) or UK (county + postcode, normalised) addresses; `country_code` per address | tenant isolation |
| `companies`, `contacts` | Directory of owners, consultants, subs, suppliers | tenant isolation |
| `projects` | Project record, contract basics, US public-works flags | tenant isolation (+ app-level team visibility) |
| `project_members` | Project team with project role | tenant isolation |
| `project_parties` | Company's role on a project | tenant isolation |
| `project_phases` | Ordered phases with dates and status | tenant isolation |
| `documents` | Logical document with metadata | tenant isolation (+ project visibility in app) |
| `document_versions` | Immutable file versions (hash, size, storage key) | tenant isolation; trigger blocks content changes |
| `cost_code_sets` | Customer-defined coding structure: name, `level_names[]`, template key (rev. 0003) | tenant isolation |
| `cost_codes` | Codes with parent/level, unit, active flag; unique per set | tenant isolation; tenant-consistent self-reference |
| `estimates` | Estimate/cost plan per project: type, cost code set, currency | tenant isolation |
| `estimate_versions` | draft/issued/approved; price base date; totals snapshot on issue | tenant isolation; **trigger freezes issued/approved** (only issued→approved allowed) |
| `estimate_lines` | Quantity (19,4), unit, labour hrs/unit (19,4), rates (19,6), waste % (5,2), line type, scope (base/alternate/excluded) | tenant isolation; trigger blocks changes unless parent version is draft |
| `estimate_markups` | Ordered % markups (9,4) on direct cost or running total; `include_in_budget` | tenant isolation; same trigger |
| `budgets` | Original budget per project: draft/approved, source estimate version, total snapshot; one approved original per project | tenant isolation; **trigger freezes approved budgets** |
| `budget_lines` | Cost code, description, amount (19,2) | tenant isolation; trigger blocks changes unless parent budget is draft |
| `contracts` | Prime contract per project: form, client, retention %, payment days, dates, defects period, LDs (amount + day/week), bond, insurance, original sum at execution (rev. 0004) | tenant isolation; **trigger freezes terms after execution** (only executed→closed) |
| `contract_lines` | Contract sum analysis / schedule of values by cost code | tenant isolation; changes only while parent is draft |
| `commitments` | Subcontracts and purchase orders: vendor, form, retention, terms, scope, exclusions, original value | tenant isolation; same freeze trigger |
| `commitment_lines` | Lump sum or measured (quantity 19,4 × unit rate 19,6 → amount 19,2, server-calculated) | tenant isolation; changes only while parent is draft |
| `change_orders` | Change against exactly one executed contract or commitment (CHECK); number, reason, reference, schedule impact, notified/response-due dates, decision, approved amount snapshot (rev. 0005) | tenant isolation; **trigger freezes content once submitted and everything once decided** |
| `change_order_lines` | Signed amounts (additions/omissions), optional measured qty × rate, `budget_amount` for client-side changes | tenant isolation; changes only while parent is draft |
| `cost_import_batches` | One accounting CSV import: filename, SHA-256 (unique per project), row count, total (rev. 0006) | tenant isolation |
| `cost_transactions` | Ledger entry: date, cost code, type (actual/accrual), amount (signed 19,2), reference, vendor, commitment link, import batch, `reverses_id` (unique partial index) | tenant isolation; **append-only: SELECT/INSERT grants only and trigger blocks UPDATE/DELETE** |
| `forecasts` | Monthly forecast per project (unique project + first-of-month period, CHECK); status draft/approved; revenue adjustment + reason; snapshot of all totals at approval | tenant isolation; **trigger freezes approved forecasts** |
| `forecast_lines` | Per cost code (NULLS NOT DISTINCT unique): CTC method, manual CTC + note, snapshot of RB/CM/CTD/CTC/FFC/variance | tenant isolation; changes only while parent is draft |
| `payment_applications` | Pay application / valuation per executed contract: number (unique per contract), period, dates (due, final payment, pay-less notice), retention %, snapshot at submission (original sum, net changes, work, stored, retention, previous certified, amount due), certificate and payment (rev. 0007) | tenant isolation; **trigger freezes the claim once submitted, the certificate once certified, everything once paid**; partial unique index: one draft/submitted per contract |
| `payment_application_lines` | Schedule-of-values line from a contract line or an approved change order (CHECK one source): scheduled value, previous work, this period, materials stored | tenant isolation; changes only while parent is draft |
| `audit_events` | Append-only audit log | read: current tenant; insert: current tenant or tenant-less security events; trigger blocks UPDATE/DELETE/TRUNCATE for every role |

### Database roles

| Role | Used by | Privileges |
|---|---|---|
| `qs_owner` | Alembic migrations only | Owns schema and tables |
| `qs_app` | Running API | `NOSUPERUSER NOBYPASSRLS`; DML on business tables, `SELECT/INSERT` only on `audit_events`, `SELECT` only on `permissions`, no DDL |

### Functions

| Function | Purpose |
|---|---|
| `app_current_tenant()`, `app_current_user()` | Read transaction-local settings (NULL-safe) for policies |
| `auth_find_user_by_email(text)` | Login / registration / invitation lookups before a user context exists |
| `auth_find_session_by_token_hash(text)` | Refresh-token rotation |
| `auth_find_invitation_by_token_hash(text)` | Invitation preview and acceptance |
| `auth_tenant_slug_exists(text)` | Unique slug allocation at registration |

All `SECURITY DEFINER` functions pin `search_path` and are `EXECUTE`-granted only to `qs_app`.

## 5. Migration policy

* Every schema change is an Alembic revision reviewed like code; destructive changes use expand → migrate →
  contract across releases.
* Security SQL for a revision lives in `alembic_helpers/<revision>_*.py` and is frozen once shipped.
* Seed data (permissions, system roles) is frozen inside the migration that introduced it; a test asserts the
  database catalog equals `app/domains/tenancy/permissions.py`.
* Revisions 0001–0007 are frozen once pushed; further changes require new revisions.
